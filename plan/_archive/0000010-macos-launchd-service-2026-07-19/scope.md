## In Scope

- macOS: `.plist` template for a user LaunchAgent (`~/Library/LaunchAgents/com.planifest.telemetry-mcp.plist`), `RunAtLoad` + `KeepAlive.SuccessfulExit: false` (req-001).
- macOS: `scripts/service-macos.sh install|uninstall|status|restart`, wired to `npm run service:*`, mirroring the existing Windows `scripts/service.ps1` command surface (req-001, req-002).
- macOS: detection + clear error path + sudo fallback for a non-writable `~/Library/LaunchAgents` (req-003).
- macOS: setup docs in `getting-started.md`/`mac-setup.md` (req-004).
- Linux: systemd **user** unit (`~/.config/systemd/user/planifest-telemetry-mcp.service`), `Restart=on-failure` (req-005).
- Linux: `scripts/service-linux.sh install|uninstall|status|restart`, wired to `npm run service:*` (req-005, req-006).
- Linux: detection + clear guidance for missing `systemctl` and for disabled session lingering (req-005, req-007).
- Linux: setup docs in `getting-started.md`/`mac-setup.md` (req-008).
- `emit_event` MCP tool argument replaced with a real `EmitEventEnvelope` Zod object schema, giving calling models a structural scaffold instead of `z.unknown()` (req-009).
- Clear, self-diagnosable rejection errors for malformed `emit_event` calls (stringified/undefined/null/array/double-wrapped) (req-010).
- Four new event types added to schema + validation: `loop_iteration`, `phase_reversal_petitioned`, `phase_reversal_granted`, `phase_reversal_denied` (req-011).
- `emit_event` tool argument renamed `event` → `envelope` (req-012).
- `package.json` version drift fix; `component.yml`/`product.yml` established as the enforced version source going forward.
- Full regression/unit/integration test coverage for all of the above, following this repo's existing `tests/unit|integration|regression` convention.
- An ADR for the tool-argument schema redesign decision (Zod gate vs. relying on ajv alone).

## Out of Scope

- A system-level (root) launchd daemon or root-level systemd unit under `/etc/systemd/system/` — the backend is per-user; no system daemon variant is built.
- Changing the backend's default port (`3741`) or DB location (`~/.planifest/telemetry.db`).
- Distro-specific packaging (`.deb`/`.rpm`) — the systemd unit is installed by a plain shell script, matching the macOS/Windows scripts.
- `ratchet_blocked` event type — recommended in the framework's REC-006 but not currently emitted by any skill; adding unused schema surface is speculative and explicitly excluded.
- Re-verifying, from this repo's side, that `planifest-framework`'s pipeline runs actually receive `phase_start`/`phase_end`/`loop_iteration` post-deploy — that verification happens in the sibling repo as a follow-up step, not as part of this pipeline run.
- WSL2 support as a distinct fourth platform variant — `linux-systemd-reference.md` notes WSL2 may already be covered by the systemd path, but this is unexplored and not a commitment of this feature.

## Deferred

- Auto-detecting and fixing a root-owned `~/Library/LaunchAgents` automatically — blocked until a human confirms it's safe to override what may be an intentional MDM/endpoint-security control. Current behaviour: clear error + manual sudo remediation (req-003).
- Auto-enabling lingering (`loginctl enable-linger`) without asking — blocked until a human decides that a persistent, account-wide setting change is acceptable on a given machine. Current behaviour: explain + print the exact command (req-007).
- npm publish of `structured-telemetry-mcp` — carried forward from 0000008, still blocked on a decision to make the package public. Unaffected by this feature.
