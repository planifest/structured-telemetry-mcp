## Context

MCP servers can communicate with agent tools via two primary transports:
- **stdio**: the agent tool spawns the server as a child process and communicates over stdin/stdout.
- **HTTP/SSE**: the server listens on a port; the agent tool connects over HTTP.

The deployment model confirmed in the design is a **local dev tool** — the server runs on the developer's machine alongside their agent tool. The server is not shared across machines, not accessed over a network, and not hosted remotely (deferred).

This decision is costly to reverse: changing transport requires updating every agent tool's configuration and potentially the setup CLI.

---

## Decision

Use **stdio transport** exclusively for v1.

stdio is the natural fit for a local tool: the agent tool (Claude Code, Cursor, etc.) spawns the MCP server as a child process and communicates over stdin/stdout. There is no port to configure, no firewall to open, no auth to implement. The server lifecycle is tied to the agent session.

HTTP/SSE transport is explicitly deferred to a future pipeline run when a hosted deployment use case emerges.

---

## Alternatives Considered

| Alternative | Pros | Cons | Why Rejected |
|-------------|------|------|-------------|
| HTTP/SSE transport | Supports remote access; multiple agents can share one server | Requires port management, firewall config, and auth; adds operational complexity for a local tool | Over-engineered for the confirmed deployment model; deferred |
| WebSocket transport | Low-latency bidirectional; good for streaming | Same operational complexity as HTTP/SSE; not yet standard in MCP ecosystem | Deferred with HTTP/SSE |
| Both stdio + HTTP/SSE | Flexible | Doubles the surface area to maintain and test | YAGNI — hosted use case is explicitly deferred |

## Consequences

**Positive:**
- Zero network configuration — no port conflicts, no firewall rules, no auth tokens.
- Server lifecycle is managed by the agent tool — no separate daemon to start or monitor.
- Setup is a single config file entry pointing to `server.bundle.mjs`.
- Consistent with context-mode-mcp's deployment model — developers already understand it.

**Negative:**
- Only one agent tool can use the server per machine session (the one that spawned it).
- Remote or team-shared telemetry requires HTTP/SSE, which must be built in a future run.
- If the agent tool crashes, the server terminates and in-flight events may be lost.

**Risks:**
- If a hosted use case becomes urgent, adding HTTP/SSE transport is a non-trivial rework of `src/server.ts` and the setup CLI (R-A002).
